## 📝 Post Service

**Post Service** — микросервис управления постами (публикациями) в составе микросервисной платформы форума.
Сервис отвечает за создание, хранение, обновление и обработку постов, а также за взаимодействие с другими микросервисами через **gRPC** и события **Kafka**.
Post Service изолирован от внешнего доступа и используется исключительно внутри платформы.

Сервис является частью проекта **[Microservices_Site](https://github.com/Weit145/microservices_site)**.


### 🔧 Зона ответственности

* **CRUD-операции с постами** через gRPC, включая:
  * `CreatePost`: создание поста.
  * `GetGroupPost`, `GetByIdPost`, `GetByIdUserPost`: получение постов.
  * `PutPost`: обновление поста.
  * `DeletePost`: удаление поста.
* Хранение данных постов в собственной базе данных PostgreSQL (`postgres_post`).
* Обеспечение целостности данных при удалении связанных сущностей (например, пользователей).

### 🧩 Взаимодействие в системе

* **Предоставляет gRPC API** для **API Gateway**, который, в свою очередь, предоставляет HTTP API для клиентских приложений.

* **Является gRPC-клиентом** для:
  * **[User-service](https://github.com/Weit145/user-service)**: для получения информации о пользователях (например, имени пользователя по ID), чтобы обогащать данные постов.

* **Потребляет события из Kafka** для поддержания согласованности данных:
  * `delete`: для удаления всех постов пользователя, когда сам пользователь удаляется.
  * `admin_delete_post`: для удаления конкретного поста по запросу от `admin-service`.

* Использует собственную изолированную базу данных `postgres_post`;
* Не имеет прямого HTTP-доступа извне.


### 🛡️ Безопасность и примечания

* Вся логика обработки постов централизована в сервисе.
* gRPC-контракты определяются в каталоге `proto`.
* Интеграция с Kafka используется для синхронизации событий между сервисами.
* Сервис масштабируется независимо от других компонентов системы.
